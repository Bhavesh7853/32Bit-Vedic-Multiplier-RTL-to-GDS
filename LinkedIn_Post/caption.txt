From RTL to GDSII: Open-Source ASIC Implementation of a 32-bit Vedic Multiplier

Over the past few days, I worked on my first complete ASIC implementation project, taking a hierarchical 32-bit unsigned Vedic multiplier from Verilog RTL through physical design and final GDSII using open-source tools on Ubuntu through WSL.

The design uses the Urdhva Tiryagbhyam multiplication structure. Four smaller Vedic multiplier blocks generate partial products at each level, while ripple-carry adders combine them to produce the final 64-bit result.

Technology and tools:
🔹 Nangate45 / FreePDK45 45 nm technology
🔹 Icarus Verilog for RTL and gate-level simulation
🔹 GTKWave for waveform inspection
🔹 Yosys for logic synthesis and technology mapping
🔹 OpenSTA through OpenROAD for timing and power analysis
🔹 OpenROAD for floorplanning, PDN, placement, routing, extraction, and reporting
🔹 KLayout for final GDSII inspection
🔹 Tcl scripts for flow automation

The work covered:
✅ Hierarchical Verilog RTL design
✅ Self-checking functional verification
✅ Logic synthesis and gate-level netlist generation
✅ Gate-level functional verification
✅ Timing constraints using a 10 ns virtual clock
✅ Design initialization and floorplanning
✅ Power planning and I/O pin placement
✅ Global placement, timing repair, and detailed placement
✅ CTS-stage evaluation for the combinational design
✅ Global and detailed routing
✅ Parasitic extraction and post-route timing/power analysis
✅ Routing DRC and antenna checks
✅ Final DEF and GDSII generation

Verification and implementation results:
• 1,007/1,007 RTL tests passed
• 1,007/1,007 gate-level tests passed
• Die area: 360 × 380 µm
• Core utilization: 12%
• Routing DRC violations: 0
• Antenna net and pin violations: 0
• Estimated total power: 95.4 mW

During the project, I found and corrected a carry-chain issue in the 32-bit ripple-carry adder. I also updated deprecated OpenROAD routing commands to make the flow work with the current tool version.

The design is combinational, so it has no physical clock tree. A 10 ns virtual clock is used for interface timing analysis. The current post-route result has a small setup WNS/TNS of −0.042 ns and some high-fanout slew/capacitance violations, which I plan to optimize next.

This project gave me practical exposure to the complete open-source ASIC flow and helped me understand how RTL decisions affect synthesis, timing, placement, routing, and final layout.
